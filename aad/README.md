# AAD — Adversarial Attack Detector reproduction

Reproduction of Verma et al., *A Secure Adversarial Attack Detector Framework for
Monitoring Network Intrusion in IoT Environment*, IEEE TCE 71(4), 2025.
DOI 10.1109/TCE.2025.3614806

## Setup

Nothing under `data/` or `artifacts/models/` is in version control — it is either
downloaded (684 MB of raw CSVs) or regenerated by the scripts (~460 MB). A fresh
clone therefore needs three steps before anything will run.

**1. Environment.** Python 3.10 or 3.11; TensorFlow 2.13 has no wheels for 3.12+.

```powershell
py -3.10 -m venv ..\.venv
..\.venv\Scripts\Activate.ps1
pip install -r ..\requirements.txt
```

TensorFlow 2.13 is CPU-only on native Windows (GPU support ended at 2.10). The
models here are small enough that this costs minutes, not hours.

**2. Download the raw data** into `data/raw/`. Two files from the CSE-CIC-IDS2018
public bucket, ~684 MB total, no AWS account needed:

```powershell
aws s3 cp --no-sign-request --region eu-west-3 `
  "s3://cse-cic-ids2018/Processed Traffic Data for ML Algorithms/Friday-16-02-2018_TrafficForML_CICFlowMeter.csv" data\raw\
aws s3 cp --no-sign-request --region eu-west-3 `
  "s3://cse-cic-ids2018/Processed Traffic Data for ML Algorithms/Friday-23-02-2018_TrafficForML_CICFlowMeter.csv" data\raw\
```

No AWS CLI? The same two files are on Kaggle (`solarmainframe/ids-intrusion-csv`);
download them manually and keep the filenames exactly as above, since
`config/data.yaml` refers to them by name.

**3. Rebuild the ignored artefacts** by running the phases in order. Everything is
seeded (`seed: 42`), so you get identical splits and the same tables.

| Step | Command | Produces | Time |
| --- | --- | --- | ---: |
| Verify setup | `python scripts\01_prepare.py --sample-frac 0.02` | throwaway smoke test | ~50 s |
| Phase 1 | `python scripts\01_prepare.py` | `data/interim/`, `data/processed/` | ~2 min |
| Phase 1b *(optional)* | `python scripts\01_prepare.py --no-dedup --out-dir data/processed_paperparity --tag paperparity` | `data/processed_paperparity/` | ~1 min |
| Phase 2 | `python scripts\02_train_baselines.py` | `artifacts/models/*.keras` | ~2.8 h CPU |

Run the smoke test first — it exercises the whole pipeline in under a minute and
fails loudly if the CSVs are missing or truncated.

Phase 2 is the long pole: MLP ~3 min, CNN ~42 min, LSTM ~2 h on CPU. Use
`--models mlp` to train just one, or `--epochs 5` for a quick end-to-end check.

The `artifacts/reports/` tables **are** committed, so you can compare your run
against the reference numbers without regenerating anything.

## Phase 1 — data pipeline

```powershell
python scripts\01_prepare.py --sample-frac 0.02   # smoke test
python scripts\01_prepare.py                      # full run
```

Reads the two CSE-CIC-IDS2018 capture files from `data/raw/` and writes:

| Path | Contents |
| --- | --- |
| `data/interim/combined.parquet` | cleaned, pre-split, unscaled |
| `data/processed/{train,val,test}.npz` | `X` float32 in [0,1], `y` binary, `y_multiclass` |
| `data/processed/scaler.pkl` | MinMaxScaler **fitted on train only** |
| `data/processed/feature_names.json` | retained feature order — downstream phases must match this |
| `artifacts/reports/class_stats.{csv,md}` | Table I |
| `artifacts/reports/prepare_meta.json` | full cleaning ledger for the write-up |

Every knob lives in `config/data.yaml`.

### Phase 1 result — two dataset variants

Deduplication is the one judgement call in this phase, and it is not cosmetic.
CSE-CIC-IDS2018 carries 594,987 exact duplicate rows across these two days, and
they are not spread evenly:

| Class | Raw rows | After dedup | Retained |
| --- | ---: | ---: | ---: |
| Benign | 1,494,781 | 1,350,659 | 90.4% |
| DoS attacks-Hulk (Type1) | 461,912 | 145,199 | 31.4% |
| **DoS attacks-SlowHTTPTest (Type2)** | **139,890** | **55** | **0.04%** |
| Brute Force -Web (Type3) | 362 | 340 | 93.9% |
| Brute Force -XSS (Type4) | 151 | 150 | 99.3% |
| SQL Injection (Type5) | 53 | 51 | 96.2% |

SlowHTTPTest produces near-identical CICFlowMeter vectors, so 99.96% of it is
literal repetition of 55 distinct flows.

Both variants are built:

```powershell
python scripts\01_prepare.py                                  # -> data/processed/          (deduped, default)
python scripts\01_prepare.py --no-dedup `
    --out-dir data/processed_paperparity --tag paperparity    # -> data/processed_paperparity/
```

Leakage probe (test rows byte-identical to a training row, sampled 50k against 200k):

| Variant | Overlap | Train rows | Attack share |
| --- | ---: | ---: | ---: |
| `data/processed` (deduped) | **0 / 50,000** | 1,047,517 | 9.74% |
| `data/processed_paperparity` | **11,017 / 50,000** | 1,464,008 | 28.80% |

Use `data/processed` as the primary. Keep the parity variant to show *why* the
literature reports 99.98% accuracy on this dataset.

## Phase 2 — baseline NIDS

```powershell
python scripts\02_train_baselines.py                 # all three
python scripts\02_train_baselines.py --models mlp    # one
```

All three take a flat `(68,)` input and emit a 2-unit softmax under
CategoricalCrossentropy. CNN and LSTM reshape to `(68, 1)` *inside* the graph, so
every model shares one input space — phase 3 can then perturb all three in the
same 68-dim domain and one validator/discriminator serves all of them.

### Table III — clean test set (224,469 rows; 21,870 attack / 202,599 benign)

| Model | Accuracy | Precision | Recall | F1 | Loss | FPR | Epochs | Train time |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| MLP | 99.9898% | 99.9817% | 99.9131% | 99.9474% | 0.00055 | 0.0020% | 20 | 162 s |
| CNN | 99.9791% | 99.9771% | 99.8080% | 99.8925% | 0.00080 | 0.0025% | 30 | 2,541 s |
| LSTM | 99.6997% | 97.5588% | 99.4056% | 98.4735% | 0.01702 | 0.2685% | 30 | 7,166 s |

Same ordering as the paper (MLP > CNN > LSTM), all above the 99.5% target.

### Detection rate per attack type (%)

| Class | Support | MLP | CNN | LSTM |
| --- | ---: | ---: | ---: | ---: |
| Benign | 202,599 | 99.998 | 99.998 | 99.731 |
| Type1 DoS-Hulk | 21,780 | 99.995 | 100.000 | 99.775 |
| Type2 DoS-SlowHTTPTest | 9 | 100.000 | 100.000 | 100.000 |
| Type3 BruteForce-Web | 51 | 66.667 | 49.020 | **0.000** |
| Type4 BruteForce-XSS | 23 | 95.652 | 39.130 | **0.000** |
| Type5 SQL-Injection | 7 | 100.000 | 71.429 | **0.000** |

Headline accuracy is carried entirely by Hulk and Benign. The three web-attack
classes are 81 test rows out of 224,469, so missing all of them costs 0.036% of
accuracy — which is exactly what the LSTM does. Report this table beside Table III;
a single accuracy figure hides it completely.

`training.class_weight: true` in `config/models.yaml` trades headline accuracy for
rare-class recall if you want the comparison.
